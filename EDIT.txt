AURUMMIND AI - PROJECT GUIDE
==========================

Purpose
-------
AurumMind AI is a Python research project for analyzing historical gold-versus-
US-dollar (XAUUSD) price candles and experimenting with forecasts of future
price direction or returns. It is intended for education and research. It is
not a broker, live trading bot, financial adviser, or order-execution system.

In plain language, the intended workflow is:
1. Load historical candle data from a CSV or Parquet file.
2. Check that the data is well-formed and report quality problems.
3. Study price, return, volatility, volume, and intraday patterns.
4. Create indicators and other features from the historical candles.
5. Train conventional machine-learning models to predict a future outcome.
6. Test models over time, examine their behavior in different market regimes,
   simulate a strategy with costs, and inspect why a model made predictions.

The project is organized as a research pipeline, not as a ready-to-run,
continuously updating prediction service.


THE DATA: EXACTLY WHERE IT COMES FROM
-------------------------------------
There are two different things to distinguish:

1. The configured / intended provider:
   configs/data.yaml names "Dukascopy" as the data_source. .env.example also
   gives DATA_SOURCE=Dukascopy as an example setting. This is a label/config
   value; it does not itself download anything.

2. The data actually bundled with the project:
   data/raw/samples/XAUUSD_1h_sample.csv
   data/raw/samples/XAUUSD_4h_sample.csv
   data/raw/samples/XAUUSD_1d_sample.csv
   data/raw/samples/XAUUSD_1h_with_issues.csv

   These sample files are synthetic test data generated by
   scripts/generate_sample_data.py. The generator creates a reproducible
   random-walk-like price series (NumPy random seed 42), starting around
   2050, then constructs OHLC candles and random-looking volume values.
   The documented generated sizes are 720 hourly candles (about 30 days),
   540 four-hour candles (about 90 days), and 365 daily candles (about a year),
   starting on 2024-01-01. The "with_issues" file is deliberately made from
   sample data and has a duplicate timestamp, a missing volume, and an
   invalid high/low relationship for validator testing.

   These files are examples for testing code; they are not historical
   exchange/broker quotes and should not be used to draw conclusions about
   real gold markets. In particular, their volume is generated noise and
   should not be interpreted as actual traded volume.

There is no provider downloader or API integration in the current ingestion
code. The loader reads files from a path supplied by the user. README.md's
"Using Real Market Data" section describes supplying your own OHLCV CSV and
passing its path and provider name to IngestionPipeline. Parquet input is also
supported. Consequently, the exact source of any real dataset used is
whatever provider/account/export the user supplies; this repository does not
fetch Dukascopy data automatically or establish that a supplied file came
from Dukascopy. The provider name recorded in ingestion metadata is supplied
by the caller.

Expected candle fields:
  timestamp, open, high, low, close, volume

The configured timeframes are 1h, 4h, and 1d, and timestamps are normalized
to UTC. For real data, check the provider's volume meaning, timezone, price
adjustments, missing periods, and licensing/usage terms.


WHAT HAPPENS TO THE DATA
------------------------
1. Ingestion - src/aurummind_ai/ingestion/
   DataLoader reads CSV or Parquet, normalizes column names, checks required
   fields, sorts rows by timestamp, and normalizes timestamps to UTC.
   IngestionPipeline coordinates loading, validation, raw Parquet storage,
   and a quality report. Metadata records the source name, instrument,
   timeframe, ingestion time, file path, and record count.

2. Validation - src/aurummind_ai/validation/
   Checks include duplicate timestamps, missing values, invalid OHLC
   relationships, negative/zero prices, suspicious price jumps, and missing
   candles. It produces a report and score. This is validation/reporting;
   it does not automatically repair market data.

3. Exploratory analysis - src/aurummind_ai/market_analysis/ and notebooks/
   Calculates price/return statistics, volatility, candle properties,
   outliers, and volume/intraday summaries. Plotly is used for interactive
   charts; notebooks/ contains data audit and exploratory-analysis notebooks.

4. Feature generation - src/aurummind_ai/features/
   Builds technical indicators such as SMA/EMA moving averages, RSI, MACD,
   Bollinger Bands, ATR, ADX, stochastic oscillator, rate of change, and
   on-balance volume. Price-action features include returns over multiple
   periods, momentum, rolling statistics/volatility, gaps, candle structure,
   market structure, and support/resistance-related features. The README
   describes the output as 80+ features. Feature generation is configured
   for 1h, 4h, and 1d data and writes Parquet plus metadata when run through
   scripts/generate_features.py.

5. Target and model training - src/aurummind_ai/models/ and
   scripts/train_models.py
   The default configs/models.yaml task is classification with a binary
   direction target and a one-candle forecast horizon. A positive or zero
   next-period close return is labeled up (1); a negative return is down (0).
   The model code also contains three-class direction and future-return
   target helpers, and regression model classes.

   The implemented model families are conventional machine learning:
   - Scikit-learn Logistic Regression.
   - Scikit-learn Random Forest classifier (and regressor support).
   - XGBoost gradient-boosted trees.
   - LightGBM gradient-boosted trees.

   The training script currently trains classification models, using
   chronological train/validation/test splits rather than shuffling time
   series rows. It trains Logistic Regression, Random Forest, XGBoost, and
   LightGBM, then reports and compares metrics such as accuracy, precision,
   recall, F1, and ROC-AUC. The default script is configured to look for
   engineered 1h features.

6. Evaluation - src/aurummind_ai/evaluation/ and scripts/evaluate_models.py
   Available evaluation code includes classification/regression metrics,
   walk-forward validation (repeated train/test windows over time), market
   regime analysis (volatility and trend categories), backtesting with
   configurable transaction costs and slippage, risk/performance statistics,
   performance attribution, and error analysis. These tools assess a model
   or simulated strategy; they do not prove future profitability.

7. Explanations - src/aurummind_ai/explainability/
   Includes SHAP explanations, built-in/permutation/drop-column feature
   importance, partial dependence and ICE analyses, and individual prediction
   explanations/counterfactual utilities. These help inspect model behavior;
   they do not establish that a prediction is correct or causal.


MACHINE LEARNING OR DEEP LEARNING?
----------------------------------
The implemented forecasting models found in the source are machine-learning
models based on linear classification and decision-tree ensembles (Logistic
Regression, Random Forest, XGBoost, LightGBM). The feature and evaluation
pipeline is designed around these tabular models.

PyTorch (torch) is listed as a dependency, and some documentation describes
it as a future/deep-learning technology. However, the current source does not
import or use torch and contains no implemented neural-network training
workflow/model. Therefore, do not interpret this repository as currently
training a deep-learning model. It is more accurate to say that deep learning
is contemplated by the dependency list/documentation, while the provided
training workflow is conventional machine learning.


TECHNOLOGIES
------------
Language/runtime:
  Python 3.12+; uv is recommended in setup instructions.

Data and validation:
  pandas, NumPy, PyArrow (Parquet), Pydantic (schemas), PyYAML (configuration).

Modeling and interpretation:
  scikit-learn, XGBoost, LightGBM, SHAP.
  PyTorch is declared but not used by current model source.

Analysis and tests:
  Plotly, Jupyter notebooks, pytest.

Development checks:
  Ruff (lint/format) and MyPy (static type checking).

Declared/planned platform technologies:
  MLflow, Apache Airflow, FastAPI/Uvicorn, Streamlit, Docker/Docker Compose,
  and PostgreSQL support appear in dependencies/configuration or project files.
  Their presence in the dependency list does not mean a complete deployed
  tracking, scheduling, API, dashboard, or database workflow is implemented.
  The README roadmap marks those as later work.


PROJECT STATUS AND IMPORTANT CAVEATS
------------------------------------
The repository contains code, scripts, tests, and phase documentation for
data ingestion/validation, exploratory analysis, feature engineering,
conventional ML, model evaluation, and explainability. The phase summaries
and README's opening status sections describe Phases 1-6 as complete, while
the README roadmap later in the same file still marks Phases 4-6 unchecked.
That roadmap is inconsistent/stale; the actual code is a better guide to
what is present.

Some entry points may need alignment before use: scripts/generate_features.py
writes timestamped Parquet files named features_XAUUSD_<timeframe>_....parquet,
and scripts/train_models.py searches for those Parquet files. By contrast,
scripts/evaluate_models.py's loader currently expects a CSV named
xauusd_features.csv under data/processed/<timeframe>/. This mismatch means
the evaluation script may not consume the feature-generator output without
adjusting its input path/format or preparing the file it expects.

The models.yaml file has classification and regression settings, but the
main training script currently calls the classification training workflow.
There is no automatic feed of fresh quotes, live inference service, trading
execution, or profitability guarantee described by the implemented pipeline.
Always validate data provenance and use real, appropriately licensed data
before drawing any market conclusions.


HOW TO EXPLORE THE PROJECT
--------------------------
Start with:
  README.md
  configs/data.yaml
  configs/features.yaml
  configs/models.yaml
  scripts/generate_sample_data.py
  scripts/test_ingestion.py
  scripts/generate_features.py
  scripts/train_models.py
  scripts/evaluate_models.py
  scripts/explain_model.py

Typical sample-data workflow (for software demonstrations, not market
research):
  1. python scripts/generate_sample_data.py
  2. python scripts/test_ingestion.py
  3. python scripts/generate_features.py
  4. python scripts/train_models.py

The test suite is under tests/unit/. Installation instructions are in
docs/INSTALLATION.md. The project is explicitly described as educational and
research-oriented, not financial advice or an automated trading system.
